# 音频实时回环与时延显示

核验日期：2026-10-16。范围：用户提供的音频模块接线表、仓库内现有约束文件的球号对照，以及本专题的需求、时延测量定义和分阶段计划。本轮为文档轮次：没有接线、构建、烧录、采样、仪器测量或实屏验收，下列未执行项均已标注。

## 1. 需求与范围（用户已确认）

用户 2026-10-16 要求：麦克风接音频模块输入端，耳机接模块输出端，耳机实时听到麦克风的声音（本地实时回环）；并把延迟时间实时显示在 HDMI 屏幕上；**屏幕已有画面及功能不动**。

- 本文记录上述需求为已确认需求；具体实现、测量和验收状态见 [NOW](../context/NOW.md)。
- 本专题只覆盖本地音频路径（麦克风 → 模块 → PL → 模块 → 耳机）与延迟测量/显示；不涉及 Wi-Fi、云端语音和字幕模型。
- 本地回环与云端翻译主线（[D13](../context/DECISIONS.md#d13-云端语音翻译与独立终端)、[CLOUD_SPEECH](CLOUD_SPEECH.md)）的关系（并行功能或前置时延基线）用户尚未说明，按待核实处理；本专题不改变 D13 的最终产品方向，也不替代 C1-x 的云端验收。
- 回环与云端链路若同时运行，会共用 DDR/VDMA 带宽、显示刷新和 PL 资源；资源关系与优先级需在实现前单独核对，不能假定互不影响。

## 2. 接口事实（用户提供，未实测）

来源：用户 2026-10-16 提供的接线表截图（J3 → JP2 → FPGA 引脚 → 方向）。机器可读副本见 [audio_module.json](../../hardware/z7_nano/audio_module.json)，本表与它保持同一事实。

| J3 脚 | 信号 | → JP2 脚 | FPGA 引脚 | 方向 |
|---|---|---|---|---|
| 3 | VW_I2C_SCLK | 15 | B19 | FPGA → 模块 |
| 4 | VM_I2C_SDAT | 16 | A20 | 双向 |
| 5 | VM_DACDAT | 17 | C20 | FPGA → 模块 |
| 6 | VM_BCLK | 13 | H16 | 模块 → FPGA（用户标注 MRCC 时钟脚） |
| 7 | VM_ADCDAT | 18 | B20 | 模块 → FPGA |
| 8 | VM_DADLRC | 14 | H17 | 模块 → FPGA（用户标注 MRCC） |
| 9 | VM_ADCLRC | 19 | D19 | 模块 → FPGA |
| 10 | NC | — | — | 悬空 |

由该表可读出的接口特征（**推断**，型号与数据手册待核实）：

- 数字音频为 I2S 类接口：BCLK + 采集/播放各自的 LRCLK + ADCDAT/DACDAT。
- **模块是时钟主**：BCLK、DADLRC、ADCLRC 全部由模块输出，PL 只能作从机；PL 侧不能自行产生 BCLK/LRCLK 去驱动该模块。
- 采集与播放各有独立 LRCLK，RTL 必须分别处理，不能只接一个 LRCLK 当通用声道时钟。
- 同时存在独立 ADC 与 DAC 数据线，因此可以只做数字域回环（ADCDAT → DACDAT），耳机通路的音质与音量由模块自身负责。
- codec 控制走 I2C（时钟由 FPGA 输出、数据双向）。寄存器序列、上电默认模式与是否需要配置才能出声均未核实。
- 信号命名与 WM8731 类 codec 一致，但**不得据此假定寄存器地址或默认采样率**。

本表**不是**经过原理图与实物核对的接线结论：J3/JP2 的物理针序、1 号脚方向、模块供电与逻辑电平、Bank 电压都还没有核对。按 [AGENTS 的分阶段要求](../../AGENTS.md#分阶段执行与验证)，未核对前不得把未经核实的模块或电平接到 PL I/O。

## 3. 接线前门禁：球号与已验收 HDMI 重叠

已核实的证据：

- 本项目 [hdmi.xdc](../../constraints/hdmi.xdc) 第 12–15 行把 **H16 / D19 / C20 / B19** 约束为 HDMI TMDS 的 P 端（`tmds_clk_p`、`tmds_data_p[0..2]`，`TMDS_33`）；N 端由 Vivado 派生，即 H17 / A20 / B20 一侧。
- 厂商资料 `ZYNQ_MINI开发板/08常用引脚约束文件/hdmi.xdc` 使用同一组球号做 TMDS。

用户音频表中的 7 个球号（B19、A20、C20、H16、B20、H17、D19）与这四对 TMDS 差分引脚重合。

待核实：当前使用的 Z7-Nano 板卡上，HDMI 显示实际占用的球号（新板约束由构建脚本生成在 `output/z7_nano/config/hdmi.xdc`，不在仓库内）以及 JP2 各针的球号定义（需 Z7-Nano 原理图与实物丝印）。

**门禁（接线前必须完成）**：

1. 用新板原理图/丝印核对 JP2 引出球号，以及当前 HDMI 实际球号；二者若重叠，"保留现有 HDMI 画面"与"按本表接音频"不能同时成立。
2. 重叠时按 ESP8266 的既有做法重新选点：先核对原理图空闲 I/O，再固定到 `hardware/z7_nano/` 下的接线事实文件，最后才写约束（见 [ESP8266 连接](../context/MAP.md#esp8266-连接)）。
3. 核对前不得按本表接线、不得生成音频引脚约束、不得修改现有 [hdmi.xdc](../../constraints/hdmi.xdc)；现有显示链路是已验收基线。

## 4. 时延测量定义

"延迟"必须按测量点分层，三层不能混用同一个数字（也未测得任何一层）：

| 层级 | 测量点 | 计划方法 | 用途 |
|---|---|---|---|
| L1 数字回环 | ADC 样本进入 PL，到同一系数样本出现在 DACDAT | PL 内样本计数/时间戳（BCLK 或系统时钟） | 回环最小延迟基线与逐次回归量 |
| L2 系统路径 | 采集入口到播放出口，含 FIFO/DDR/PS/重采样 | 两端单调计数器打点 | 评估加入软件处理后的代价 |
| L3 声学端到端 | 麦克风膜片到耳机声压 | 外部仪器或双通道录音测脉冲/包络偏移 | 用户实际可感知的延迟 |

显示规则：

- 屏幕上必须能看出所显示的是哪一层、哪个测量点；只有 L1/L2 时可显示"数字域"标记，不得让人误读为声学延迟。
- 未测得时显示"未测量"；不得用估算值、理论值或历史值冒充实测（沿用 [AGENTS](../../AGENTS.md#分阶段执行与验证) 对"仿真/构建/测量/验收"分别记录的要求）。
- 读数刷新不得阻塞视频扫描或改变现有已验收的布局、控件和交互；新增读数会改变像素，因此不能用旧的全帧零差异结论覆盖本轮实屏验收（界面职责见 [UI_SPEC](UI_SPEC.md#时延读数)）。

## 5. 方案建议（未确认、未实施）

- **最小延迟优先**：先在 PL 内做 ADCDAT → DACDAT 直通（同一 BCLK 域内的少量寄存器，或跨域异步 FIFO），不经 PS/DDR。这样 L1 与 L3 的差主要来自 codec 内部与模拟前端，也便于把"软件处理代价"从基线中分离。
- **需要软件处理时**再引入 PS 路径：PL 采集 → AXI DMA → DDR → PS 播放，接口沿用 [INTERFACES](INTERFACES.md#2-pl-到-ps-的音频接口) 的 `s16le` 单声道约定；此路径的延迟按 L2 单独测量。
- **codec 配置**：若上电默认模式不可用，优先用 PS 侧 I2C（MIO）而不是占用 PL I/O；具体总线与地址待型号核实后决定。
- **时钟与约束**：BCLK 作为外部输入时钟需显式 `create_clock` 并配套 `set_input_delay`；用户标注 MRCC 与时钟资源、Bank 电压和 IOSTANDARD 需在原理图与器件手册上核对后才能写约束。RTL 侧按 [hdmi_clock.v](../../rtl/hdmi_clock.v)/[async_rst_sync.v](../../rtl/async_rst_sync.v) 的既有路线处理时钟与异步复位，不新造风格。
- 以上均为建议；未记录为用户已确认的技术决定，也未产生代码或约束。
