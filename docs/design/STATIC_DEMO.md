# PL 静态 UI 实现

适用范围：本文是 2026-10-10 旧 RevB 纯 PL 静态演示，文字/触摸未接入是该演示的真实边界，不是当前产品能力。现行 Z7-Nano 使用 PS 实时渲染；UI 历史页不能靠生成静态图片替代，状态见 [NOW](../context/NOW.md)。

日期：2026-10-10；用户要求先把演示静态画面配置到已有板卡。它是实屏布局样稿，不能替代实时 PS UI、触摸或音频验证。

## 画面与存储

从现有 [HTML](../../output/ui/index.html) 生成一屏带两条模拟记录的画面，明确标注“静态演示”“模拟文案”“触摸与音频功能尚未接入”。仅快照覆盖显示状态，不改浏览器原型文件。

使用固定 16 色调色板，保留文字、底色与青绿色主动作；关闭抖色以提高小块复用。按 8×8 像素分块，每行 128 块、共 75 行；相同小块只保存一次。真实资产数量、哈希、像素还原与容量估算以 [asset_manifest](../../output/static_ui/asset_manifest.json) 为准，实际片内存储用量以实现报告为准。

图片生成入口：[render_static_ui.py](../../scripts/render_static_ui.py)。[量化预览](../../output/static_ui/ui_quantized.png) 是板上预期目标；完整 RGB 原图和量化图颜色会有轻微差异。

## 像素链路

`光栅坐标 → tile_map 同步 ROM → tile_pixels 同步 ROM → palette → 已验证 TMDS 发送器`。

两次同步查表形成两拍延迟，HS/VS/DE、观测坐标和帧计数按相同延迟输出；消隐区读安全地址并输出黑色。ROM 输出不加异步复位，保持 BRAM 推断；异步复位作用于光栅与有效信号。

光栅与电气参数沿用 MAP 指向的 HDMI 基线，不同时改变分辨率、时钟或引脚。参考厂商的 [ROM_STYLE](https://docs.amd.com/r/en-US/ug901-vivado-synthesis/ROM_STYLE) 与 [ROM 编码方式](https://docs.amd.com/r/en-US/ug901-vivado-synthesis/ROM-HDL-Coding-Techniques)，最终由综合报告确认推断结果。

## 验证与限制

图像生成器独立解码小块后核对全部像素；RTL 仿真直接读取完整画面参考，不用 DUT 的小块查找过程生成期望值。两个有效画面共检查 1228800 个像素，并检查同步、消隐和复位。

编码器另用独立整数模型检查 2344 个符号，覆盖全部 256 个输入值与 4 个控制码。顶层接收器从 TMDS 输出引脚逐位恢复时钟与三个颜色通道；在首次 HS 控制码切换处仅对齐一次，之后连续核对 140000 个 10 位字，覆盖有效像素、消隐和颜色通道差异，不靠“输出有变化”判断串化正确。

下载结果在每次尝试前设为 pending，异常记为 failed；只有工具成功、DONE/EOS/CRC 正确且源码/位流仍与构建证据一致，才记为 passed。记录绑定尝试 ID、位流 SHA-256、JTAG 目标、设备与 UTC 核验时间，避免失败后沿用旧的成功状态。

静态版无需 PS/DDR 或 Linux。UI 控件只是画面像素，触摸不会产生动作；其效果不能作为原生 LVGL 或中文字库渲染的证据。读出持续运行，心跳 LED 来自帧计数；这仍不是模型或音频在运行。

操作方法见 [RUNBOOK P2a](../context/RUNBOOK.md#p2a-纯-pl-静态-ui-演示)，当前结果以 [NOW](../context/NOW.md) 为准。只有用户确认实屏后，才记录画面验收通过。
