## 2026-10-20 中文译英补充

本轮实现选择中文译英使用 Zynq TLS / ESP TCP、1 Mbps，理由是旧 ESP SSL 路径持续流故障而当前候选通过实际连续验证。范围及证据见 [ZHEN](ZHEN.md)，这不表示长期产品架构或真人听感已获用户验收。

## D1 产品主链路

- 决策：音频模块进入 Zynq，执行必要信号处理；将语音翻译为中文，通过现有 HDMI 屏显示，最终通过触摸交互。
- 来源：用户 2026-10-10 的产品需求。
- 范围：中文文字输出。这是最初范围；后续回环/译音取舍见 D15/D16，双向字幕选择见 D17。说话人分离和远场阵列未纳入当前要求。

## D15 音频实时回环与时延显示

- 决策：先在 Zynq 上打通本地音频实时回环（麦克风 → 音频模块 → 板卡 → 模块 → 耳机），并把延迟时间实时显示在 HDMI 屏幕上；屏幕已有画面及功能不动。
- 来源：用户 2026-10-16 的需求与音频模块接线表（J3 → JP2 → FPGA 引脚 → 方向）。
- 范围：本地音频路径、延迟测量与屏显；不改动已验收的显示布局与交互，不替代 [D13](#d13-云端语音翻译与独立终端) 的云端链路，也不涉及 Wi-Fi、字幕模型与云端凭据。本轮未接线、未构造约束、未构建、未测量。
- 实施选择：模块自带 12.288 MHz 晶振，PL 作 I2S 从机；但必须先经 I2C 写 WM8731 的 R7（主模式）/R9（使能）等寄存器，模块才会输出 BCLK/LRCLK，因此 I2C 初始化是实现前置（见 [RISKS](RISKS.md) R18）。最小延迟优先在 PL 内做 ADCDAT→DACDAT 直通；需要软件处理时再走 PS/DMA 并按 L2 单独测量。时延读数的位置由实现方决定：复用现有状态行右侧的固定宽度槽位，不改变既有布局与按钮，见 [UI_SPEC](../design/UI_SPEC.md#时延读数)。这些是建议，不是用户已确认的技术决定，承载见 [AUDIO_LOOPBACK](../design/AUDIO_LOOPBACK.md)。
- 待核实：模块 I2C 从地址（0x1A/0x1B）与供电电流/GND 针位、WM8731 完整初始化序列（见 [RISKS](RISKS.md) R1/R18）。引脚占用已核对：当前板 HDMI 在 Bank34、音频 7 个信号在 Bank35 的 JP2，不重叠；板载 EEPROM I2C 也在 Bank34，不占用音频脚（R17 已于 2026-10-16 更正）。
- 实施选择（2026-10-17 落地）：I2C 主机与 WM8731 初始化放在 PL（软 I2C + 上电自动序列，含 0x1A/0x1B 探测）；音频链路与 L1 计数全部在 PL 内、不依赖 PS；回环 FIFO 深度 2 帧并在预填充后才开播；L1 定义为“采集起点→播出”的 BCLK 周期数（不是 FIFO 占用量）；当时屏幕使用右上角 `L1 nnnn us`；2026-10-20 用户要求后改为 PS 抗锯齿 L1/T1 卡片，PL 保留测量而关闭旧文字层。这些是已实现的工程选择，可由用户指令更改；证据见 [AUDIO_LOOPBACK](../design/AUDIO_LOOPBACK.md#7-已实现2026-10-17)。
- 承载：接线事实见 [MAP](MAP.md#音频模块连接) 与 [audio_module.json](../../hardware/z7_nano/audio_module.json)；操作与验收见 [RUNBOOK](RUNBOOK.md#a-音频实时回环与时延显示后续)。

## D21 译音延迟优化（2026-10-21）

- 来源：用户确认原输出质量可用，要求优化长句后半段译音播出约4–5秒延迟，优先检查上传/下行。
- 选择：1Mbaud、ARM TLS确认上传、主动IPD下行、批量明文解析及有界服务；根据接收节奏使用1.28/2秒预缓冲。默认语速/PCM质量、UI风格及PL保持。
- 当时未采用出现欠载的640ms预缓冲和记录串口异常的2Mbaud变体；后续D22查出批量MMIO读取不可靠，不能据早期记录确认物理帧错误。不以丢句或加速掩盖延迟。测试通过与真人长句听觉验收单列，完整数据及异常见[延迟验证](../validation/tts-latency-20261021/README.md)。

## D22 连续六句的字幕与译音优化（2026-10-22）

- 来源：用户反馈连续较长语句时字幕、译音都严重延迟，要求自动用至少5–6句、每句6字以上的长难句测试。
- 自动夹具为6句、每句25–29个汉字，共40.129秒；按实时速度走板端Opus、TLS、Wi-Fi、真实云译和DAC。不将合成输入当作实体麦克风或人工准确率验收。
- 实施选择：串口提高至2Mbaud，固定点Opus改用O2编译，保持24kbps/复杂度5和原PCM/语速。主动IPD剥离包头时合并重复CRLF，清回复时同步重置长度和行偏移；600个拆分小包的原生用例先复现错误25，再通过修正。不通过增加重试掩盖故障。CPU1改为每毫秒服务USB/触摸，减少空闲重复访问。
- 测量要求：持续语音期间不进行大块JTAG读取；外设寄存器逐个读取，避免批量读取产生伪计数。完整输入、全部定稿、全部PCM消费、单次TLS连接及零故障分别核验。结果、失败对照及最终正式身份由[长句验证](../validation/long-speech-20261022/README.md)和NOW维护。

## D25 SD 卡独立启动（2026-10-26）

- 来源：用户要求“从实用性出发优化或增加功能”，在候选中选择“脱离电脑独立启动”，并提供一张 32 GB 空白 TF 卡；同轮明确板上模型提速先不做、工具链自适应和 NOW 之外的入口改动不做。
- 选择 TF 卡而非 QSPI：板载 W25Q128 只有 16 MB，装不下约 400 MB 的 Qwen 权重。不重建 PL：另建只含 PS 的平台给 FSBL，在原配置上加开 SD0 与 UART0。
- 凭据：用户确认独立启动时自动联网，配置文件放卡上（明文，卡丢即泄露，可在百炼作废 Key）。凭据由用户在终端输入，工具直接写卡，不进 `BOOT.BIN`、仓库或电脑文件。
- TLS：板子无时钟源，时间以配置文件生成时刻为基准，只在 SD 启动时忽略证书“尚未生效”标志；随机数用文件种子混合每次开机的 2048 个麦克风采样。JTAG 流程保持原样。
- 实施中补上 JTAG 加载器原先替固件做的 USB 预上电，并改成屏幕先通电满 5 秒再枚举触摸屏。结果与边界见 [SD_BOOT](../design/SD_BOOT.md) 和[验证](../validation/sd-boot-20261026/README.md)。

## D26 SD 启动后台加载板上模型（2026-10-27）

- 来源：用户要求 SD 启动“先不加载本地模型，等其他正常加载完了再加载本地模型参数”，进度在 **设置 → 模型与本地声纹** 查看，加载完弹出几秒通知后消失，目的是屏幕更快亮起。
- Qwen 权重与分词器改为卡上普通文件 `qwen.tqw`、`qwen.tok`，`BOOT.BIN` 只剩 FSBL、位流、跳板与程序（约 5 MB）。固件在屏幕、触摸和运行期配置完成后用 SD 控制器 ADMA2 直接读入原固定窗口，边读边做 SHA256，仍以固件固定摘要作为就绪条件；不改 FSBL，不重新初始化卡。
- 校验在服务循环中分片执行，避免拖慢识别与界面：首版会话中 150 µs/次（就绪 128 秒），同日按用户“继续优化”改为 400 µs/次（就绪 60 秒，加载期间麦克风 FIFO 无丢样本），空闲 600 µs/次；加载期间锁住电脑上传入口。JTAG 流程、电脑上传与热重载复核不变。设计见 [SD_BOOT](../design/SD_BOOT.md#板上模型后台加载2026-10-27)。
