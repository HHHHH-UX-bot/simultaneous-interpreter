# 已确认决策

## D1 产品主链路

- 决策：音频模块进入 Zynq，执行必要信号处理；将语音翻译为中文，通过现有 HDMI 屏显示，最终通过触摸交互。
- 来源：用户 2026-10-10 的产品需求。
- 范围：中文文字输出。语音播报、双向会话、说话人分离和远场阵列尚未要求，不作为本轮必做功能。

## D2 使用局域网电脑处理模型

- 决策：第一版允许联网，优先由局域网电脑执行语音识别与翻译。
- 来源：用户 2026-10-10 对后端方案的明确回答。
- 理由：用户选择该路径；模型推理可以独立迭代，终端保留本地采样、显示与交互职责。
- 范围：电脑继续承担后端入口；后续中文云翻译选择见 D11。具体时延须实测。

## D3 独立项目与初始范围

- 决策：在 Zynq 下新建产品项目，本轮先完成详细方案与可体验的 UI；音频和触摸配件尚未到货。
- 来源：用户本轮指令；目录采用 `simultaneous_interpreter/` 作为实施命名。
- 范围：保留同级已验证的 HDMI 和 LED 项目。这里的“不安装依赖、启动业务服务、构建或烧录”是最初方案/UI 轮次边界；后续静态下载和联网分别见 D5/D6，当前任务范围以 NOW 为准，不将初始限制当作永久禁止实现。

## D4 沿用分阶段工作约定

- 决策：按阶段取得证据后再推进依赖阶段，必要资料缺失时询问；按需读写项目资料并保留已有成果。
- 来源：用户此前长篇协作要求及本轮“coding要求还是我之前的那一大串”。
- 承载：长期规则见 [AGENTS](../../AGENTS.md)，阶段验收见 [RUNBOOK](RUNBOOK.md)。

## 尚未确认的选型

PS Linux、LVGL、具体 ASR 模型、主采样率和音频模块接口仍不是最终产品选型。中文翻译方向见 D11；第一版语言范围见 D8；界面名称“译声”仅用于讨论，不代表品牌定案。

## D5 先下载静态演示画面

- 决策：先把当前 UI 的静态演示画面配置到开发板，通过实屏查看布局。
- 来源：用户 2026-10-10 的“先把演示的静态画面烧录一下吧”。
- 实施选择：沿用已有 HDMI 电气与视频时序，使用纯 PL 的调色板/小块 ROM；不以此认定 Linux、实时 UI、音频或触摸已完成。
- 范围：本轮 JTAG 临时配置，不改写 QSPI/SD 等持久启动介质。

## D6 接入 ESP8266 验证联网

- 决策：使用用户连接的 ATK-MW8266D，经 U15/W15 与 Zynq 通信，按阶段继续串口和 Wi-Fi 联网。
- 来源：用户 2026-10-11 的接线与继续实施指令，并确认模块使用板上 3.3 V 和 GND。
- 实施选择：先用 JTAG-to-AXI 和 PL UART 独立验证模块，不替代最终 PS 软件架构决定。
- 范围：无线凭据仅运行时使用；路由器后台必要时只读检查。沿用 D2 的局域网模型方向，不自动上传音频至公网或改写 ESP 固件。

## D7 继续以完整产品为总体目标

- 决策：总体目标是完成 D1 的产品，静态画面、串口和联网阶段通过不等于总体完成；后续继续按 D4 分阶段取得证据。
- 来源：用户 2026-10-11 明确“我最终的目标是做出那个产品，继续往下干”。
- 范围：PS/DDR、动态 UI、自主网络、真实音频、触摸与模型仍需对应实现和验收。本次显式调用的 project-context-docs 仅完成文档接续；其未执行计划不构成已实现能力。
- 选型边界：不把本次提出的实现顺序、Linux/LVGL、提高波特率或压缩方案自动记成用户已确认技术决定。

## D8 第一版英语转中文

- 决策：第一版以英语输入、中文字幕输出为目标。
- 来源：用户 2026-10-11 在模型准备问题中选择“英语 → 中文”。
- 范围：不自动扩大到多语种、语音播报或公网处理；模型、电脑和代表性测试音频仍需对应核验。用户同时确认音频模块与 USB 触摸数据线尚未到货，硬件阶段保持未实施。

## D9 换为 Z7-Nano 7010 并继续产品迁移

- 决策：在现有产品项目内将板端工程移植到新 7010 板，保留旧板配置和验收成果；依旧逐阶段验证后继续。
- 来源：用户 2026-10-13 的换板指令及资料路径更正。误发的 `v4.zip` 不属于本项目资料；目标资料为 `Z7-NanoR20-7010-2018.3`。
- 实施方向：先沿用已实现的裸机 UI 与 PL HDMI，USB Host 枚举/HID 单独核验。用户倾向不使用 Linux，但有 USB Host 不等于裸机驱动已经完成。
- 当前接线与硬件来源见 [迁移专题](../design/BOARD_MIGRATION.md)，不沿用旧 ESP 接线作为新板事实；不改写 QSPI/SD 等持久启动介质。

## D10 新板继续使用 ESP8266 联网

- 决策：先接 ESP8266，继续局域网电脑处理的原型路线。
- 来源：用户 2026-10-13 在询问 PS 网口接线时回复“你把外接引脚的图发一下吧，我接一下8266”。
- 范围：网络模块路线已选择；针位由新板原理图核对后分配，见 [新板接线](../design/BOARD_MIGRATION.md#esp8266-新板接线)。实际接好、UART 固件、AT 应答和联网分别验证，不把本决定算作完成状态。

## D11 中文翻译优先使用 DeepSeek API

- 决策：优先接入官方 DeepSeek V4.1 Flash 进行英语文本到简体中文翻译；电脑负责 API 调用，语音识别先沿用现有本地模块。
- 来源：用户 2026-10-14 提出改用 DeepSeek API，并确认已有官方 API key。
- 实施选择：官方当前模型名 `deepseek-flash`，关闭思考模式，先验证一条受控文本，再接 ASR/服务和板端。接口与证据由 [MODEL_BACKEND](../design/MODEL_BACKEND.md)维护。
- 范围：英语识别文本送往官方 API；原始音频在电脑本地处理，密钥由电脑隐藏输入并保留在本次进程内存。速度、质量和模型上屏尚需分别验证，不预先认定优于旧本地模型。
