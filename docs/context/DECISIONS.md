# 已确认决策

## 2026-10-20 中文译英补充

本轮实现选择中文译英使用 Zynq TLS / ESP TCP、1 Mbps，理由是旧 ESP SSL 路径持续流故障而当前候选通过实际连续验证。范围及证据见 [ZHEN](ZHEN.md)，这不表示长期产品架构或真人听感已获用户验收。

## D1 产品主链路

- 决策：音频模块进入 Zynq，执行必要信号处理；将语音翻译为中文，通过现有 HDMI 屏显示，最终通过触摸交互。
- 来源：用户 2026-10-10 的产品需求。
- 范围：中文文字输出。语音播报、双向会话、说话人分离和远场阵列尚未要求，不作为本轮必做功能。

## D2 使用局域网电脑处理模型

- 决策：第一版允许联网，优先由局域网电脑执行语音识别与翻译。
- 来源：用户 2026-10-10 对后端方案的明确回答。
- 理由：用户选择该路径；模型推理可以独立迭代，终端保留本地采样、显示与交互职责。
- 范围：这是原型阶段的历史选择；2026-10-14 最终产品不依赖局域网电脑的决定由 D13 替代。既有电脑模型证据保留原范围。

## D3 独立项目与初始范围

- 决策：在 Zynq 下新建产品项目，本轮先完成详细方案与可体验的 UI；音频和触摸配件尚未到货。
- 来源：用户本轮指令；目录采用 `simultaneous_interpreter/` 作为实施命名。
- 范围：保留同级已验证的 HDMI 和 LED 项目。这里的“不安装依赖、启动业务服务、构建或烧录”是最初方案/UI 轮次边界；后续静态下载和联网分别见 D5/D6，当前任务范围以 NOW 为准，不将初始限制当作永久禁止实现。

## D4 沿用分阶段工作约定

- 决策：按阶段取得证据后再推进依赖阶段，必要资料缺失时询问；按需读写项目资料并保留已有成果。
- 来源：用户此前长篇协作要求及本轮“coding要求还是我之前的那一大串”。
- 承载：长期规则见 [AGENTS](../../AGENTS.md)，阶段验收见 [RUNBOOK](RUNBOOK.md)。

## 尚未确认的选型

PS Linux、LVGL、主采样率和音频模块接口仍不是最终产品选型。云端语音翻译方向见 D13；第一版语言范围见 D8；界面名称“译声”仅用于讨论，不代表品牌定案。

## D5 先下载静态演示画面

- 决策：先把当前 UI 的静态演示画面配置到开发板，通过实屏查看布局。
- 来源：用户 2026-10-10 的“先把演示的静态画面烧录一下吧”。
- 实施选择：沿用已有 HDMI 电气与视频时序，使用纯 PL 的调色板/小块 ROM；不以此认定 Linux、实时 UI、音频或触摸已完成。
- 范围：本轮 JTAG 临时配置，不改写 QSPI/SD 等持久启动介质。

## D6 接入 ESP8266 验证联网

- 决策：使用用户连接的 ATK-MW8266D，经 U15/W15 与 Zynq 通信，按阶段继续串口和 Wi-Fi 联网。
- 来源：用户 2026-10-11 的接线与继续实施指令，并确认模块使用板上 3.3 V 和 GND。
- 实施选择：先用 JTAG-to-AXI 和 PL UART 独立验证模块，不替代最终 PS 软件架构决定。
- 范围：无线凭据仅运行时使用；路由器后台必要时只读检查。沿用 D2 的局域网模型方向，不自动上传音频至公网或改写 ESP 固件。

## D7 继续以完整产品为总体目标

- 决策：总体目标是完成 D1 的产品，静态画面、串口和联网阶段通过不等于总体完成；后续继续按 D4 分阶段取得证据。
- 来源：用户 2026-10-11 明确“我最终的目标是做出那个产品，继续往下干”。
- 范围：PS/DDR、动态 UI、自主网络、真实音频、触摸与模型仍需对应实现和验收。本次显式调用的 project-context-docs 仅完成文档接续；其未执行计划不构成已实现能力。
- 选型边界：不把本次提出的实现顺序、Linux/LVGL、提高波特率或压缩方案自动记成用户已确认技术决定。

## D8 第一版英语转中文

- 决策：第一版以英语输入、中文字幕输出为目标。
- 来源：用户 2026-10-11 在模型准备问题中选择“英语 → 中文”。
- 范围：不自动扩大到多语种、语音播报或公网处理；模型、电脑和代表性测试音频仍需对应核验。用户同时确认音频模块与 USB 触摸数据线尚未到货，硬件阶段保持未实施。

## D9 换为 Z7-Nano 7010 并继续产品迁移

- 来源：用户 2026-10-13 的换板指令及资料路径更正。误发的 `v4.zip` 不属于本项目资料；目标资料为 `Z7-NanoR20-7010-2018.3`。
- 实施方向：先沿用已实现的裸机 UI 与 PL HDMI，USB Host 枚举/HID 单独核验。用户倾向不使用 Linux，但有 USB Host 不等于裸机驱动已经完成。
- 当前接线与硬件来源见 [迁移专题](../design/BOARD_MIGRATION.md)，不沿用旧 ESP 接线作为新板事实；不改写 QSPI/SD 等持久启动介质。

## D10 新板继续使用 ESP8266 联网

- 决策：先接 ESP8266，继续局域网电脑处理的原型路线。
- 来源：用户 2026-10-13 在询问 PS 网口接线时回复“你把外接引脚的图发一下吧，我接一下8266”。
- 范围：网络模块路线已选择；针位由新板原理图核对后分配，见 [新板接线](../design/BOARD_MIGRATION.md#esp8266-新板接线)。实际接好、UART 固件、AT 应答和联网分别验证，不把本决定算作完成状态。

## D11 中文翻译优先使用 DeepSeek API

- 决策：优先接入官方 DeepSeek V4.1 Flash 进行英语文本到简体中文翻译；电脑负责 API 调用，语音识别先沿用现有本地模块。
- 来源：用户 2026-10-14 提出改用 DeepSeek API，并确认已有官方 API key。
- 实施选择：官方当前模型名 `deepseek-flash`，关闭思考模式，先验证一条受控文本，再接 ASR/服务和板端。接口与证据由 [MODEL_BACKEND](../design/MODEL_BACKEND.md)维护。
- 范围：已完成一次独立文本实测，保留对照入口；2026-10-14 的最终云端语音主链路由 D13 替代。现有 DeepSeek 适配器不代表支持音频识别或已经接到板端。

## D13 云端语音翻译与独立终端

- 决策：最终产品只连接 Wi-Fi 即可运行，语音识别和翻译由云端完成，电脑仅用于开发和调试；优先验证阿里百炼实时语音翻译一体接口。
- 来源：用户 2026-10-14 明确要求云端 STT、使用时不连电脑，并选择“阿里百炼实时语音翻译一体”。
- 范围：第一版英语到简体中文，仅输出字幕并保留可选原文；沿用已经验收的裸机显示、USB 触摸和 ESP8266 接线。模型版本及接入阶段由 [CLOUD_SPEECH](../design/CLOUD_SPEECH.md)维护。
- 实施范围：北京地域凭据准备及电脑文件对照已有证据，见 [CLOUD_SPEECH](../design/CLOUD_SPEECH.md#c2-pc-受控音频云端对照)；板端持续音频、可信加密连接、独立启动和中文覆盖仍分别验收。模型/编码替代仅是候选，未记录为用户已确认决定。

## D14 新板串口使用 921600

- 决策：ESP8266 与新板的串口改为 921600、8N1；当前使用 UART_CUR 临时设置，由裸机程序启动协商，不改 ESP Flash。
- 来源：用户 2026-10-14 的“串口直接上921600吧”；临时设置沿用此前不改写 ESP 固件/启动介质的范围。
- 范围：实际 FPGA 分频、冷启动/暖重载行为及验证由 [高速 UART](../design/BOARD_MIGRATION.md#m5-2-921600-串口)维护。理论带宽不算连续音频或云端验收。

## D15 音频实时回环与时延显示

- 决策：先在 Zynq 上打通本地音频实时回环（麦克风 → 音频模块 → 板卡 → 模块 → 耳机），并把延迟时间实时显示在 HDMI 屏幕上；屏幕已有画面及功能不动。
- 来源：用户 2026-10-16 的需求与音频模块接线表（J3 → JP2 → FPGA 引脚 → 方向）。
- 范围：本地音频路径、延迟测量与屏显；不改动已验收的显示布局与交互，不替代 [D13](#d13-云端语音翻译与独立终端) 的云端链路，也不涉及 Wi-Fi、字幕模型与云端凭据。本轮未接线、未构造约束、未构建、未测量。
- 实施选择：模块自带 12.288 MHz 晶振，PL 作 I2S 从机；但必须先经 I2C 写 WM8731 的 R7（主模式）/R9（使能）等寄存器，模块才会输出 BCLK/LRCLK，因此 I2C 初始化是实现前置（见 [RISKS](RISKS.md) R18）。最小延迟优先在 PL 内做 ADCDAT→DACDAT 直通；需要软件处理时再走 PS/DMA 并按 L2 单独测量。时延读数的位置由实现方决定：复用现有状态行右侧的固定宽度槽位，不改变既有布局与按钮，见 [UI_SPEC](../design/UI_SPEC.md#时延读数)。这些是建议，不是用户已确认的技术决定，承载见 [AUDIO_LOOPBACK](../design/AUDIO_LOOPBACK.md)。
- 待核实：模块 I2C 从地址（0x1A/0x1B）与供电电流/GND 针位、WM8731 完整初始化序列（见 [RISKS](RISKS.md) R1/R18）。引脚占用已核对：当前板 HDMI 在 Bank34、音频 7 个信号在 Bank35 的 JP2，不重叠；板载 EEPROM I2C 也在 Bank34，不占用音频脚（R17 已于 2026-10-16 更正）。
- 实施选择（2026-10-17 落地）：I2C 主机与 WM8731 初始化放在 PL（软 I2C + 上电自动序列，含 0x1A/0x1B 探测）；音频链路与 L1 计数全部在 PL 内、不依赖 PS；回环 FIFO 深度 2 帧并在预填充后才开播；L1 定义为“采集起点→播出”的 BCLK 周期数（不是 FIFO 占用量）；屏幕读数固定为右上角 `L1 nnnn us`。这些是已实现的工程选择，可由用户指令更改；证据见 [AUDIO_LOOPBACK](../design/AUDIO_LOOPBACK.md#7-已实现2026-10-17)。
- 承载：接线事实见 [MAP](MAP.md#音频模块连接) 与 [audio_module.json](../../hardware/z7_nano/audio_module.json)；操作与验收见 [RUNBOOK](RUNBOOK.md#a-音频实时回环与时延显示后续)。

## D17 板端英中双向翻译切换

- 决策：顶部方向文字变为可展开按钮，只提供 English → Chinese 与 Chinese → English。
- 来源：用户 2026-10-21 新增需求；随后分别确认真实中译英、切回英译中和字号正常。
- 实施选择：复用现有 ARM TLS 和 UI 状态，改变方向时清空旧结果、隔离旧 epoch，再按运行/暂停状态关闭重连或保持暂停；不通过重新下载固件切换。
- 范围：当前 ARM TLS 双语构建；旧 ESP TLS 和独立 ASR 构建不显示无法实际完成的菜单。保留原显式构建模式与 D16 字幕优先路线。
- 交互与证据分别见 [UI_SPEC](../design/UI_SPEC.md#板端翻译方向切换2026-10-21)和[本轮验证](../validation/language-picker-20261021/README.md)，不是双向长测放行。

## D16 初版以字幕为主，保留本地回环

- 决策：初版英语转中文以原文/中文字幕为主，保留麦克风到耳机的 PL 本地回环；不把云端中文译音播放作为本阶段放行条件。
- 条件：用户随后允许在资源不足时取消本地回环。当前环回已在既有位流中，本次不新增 PL 资源；先验证输出选择，不因尚未证实的资源问题提前删除。
- 来源：用户 2026-10-21 在输出模态对照期间选择“先以字幕为主，保留本地回环（推荐）”。
- 范围：当前译音代码和对照入口保留。产品构建通过显式 `--text-only-response` 选择只请求文本，不同时改变采样、上传、VAD 或 PL 回环；构建器的历史默认值保持不变。
- 边界：该决定延续 D13 的字幕目标，不证明此前停更根因已定位。固定样本长测、真实麦克风、触摸和本地耳机听感分别验收；结果由[本次对照](../validation/text-response-20261021/README.md)维护。
