## 真实输入故障与局部修正

早期正式候选确有队列满错误9、继发网络行溢出26，不能写成连续传译稳定通过。诊断版只增加元数据记录，不记录原始语音或识别文本。

`microphone_probe2/event_trace/trace.json` 的1608条事件中，第1110条原文定稿返回schema=2、解码长度0；对应译文与response.done已经到达。队头原文未就绪，后续条目积压。代码核对发现文本解析拒绝空字符串，而业务中的空定稿清理分支因此不可达；即使可达，原分支也不会清理已有译文的槽位。

在保持事件顺序和ID关联、用非敏感短文替换内容并将该终止结果重建为空字符串的回放中，修正前ASR48/翻译49/定稿37，修正后ASR49/翻译49/正常定稿48，另有1个空结果被显式终止。旧记录没有保存字段原始类型，故该回放的空字符串重建属于受代码与长度证据支持的假设，不作为原JSON全文证据。null和缺字段仍报schema；不把预览补成最终原文。

另修正迟到预览覆盖定稿、重建已提交槽位的问题。真实麦克风诊断先有35条完整定稿，随后上述空结果使历史停在37；因此前段成功不能覆盖后段故障。

`microphone_probe3` 进一步记录到有原文final和译文预览、response.done=completed，却缺少独立的译文done；原实现只设置响应完成位，无法从其最终输出补齐译文。现按照[官方response.done结构](https://help.aliyun.com/zh/model-studio/live-translator-server-events)读取唯一、已完成的assistant输出，检查目标ID，并只从最终text/transcript补齐定稿；不把预览当作最终文字。明确空译文只记失败结果并终止对应槽位，不伪造句对；原非空final不会被空结果覆盖。有效服务错误码也不再因为说明文字是中文或过长而被忽略，沿用既有错误报告与恢复。

`session_diag[6/7/8]`分别统计空ASR终止、明确空译文终止、使用response.done最终译文补齐。最终诊断版 `microphone_probe4` 实际接受了1个空ASR，15个原文结果中14条正常定稿，队列排空；合成PCM 616320样本全部播放，欠载/上传丢页/串口错误/云失败为0。该目录build、load、现场采样及事件元数据分别绑定诊断ELF。恢复正式版后另做就绪观察，不能把旧版短测扩展为无期限可靠性。

播放诊断曾累计欠载；起播仅搬运512个样本（21 ms），即使软件有2秒数据，也无法抵御繁忙处理。现保持每次搬运预算，等实际FIFO填满8192样本或整段短译音入FIFO再开播，不隐藏原欠载计数。修正后板测另存于 `output/tts/microphone_probe3/`、`microphone_probe4/` 和最终应用目录；probe3仍有定稿故障，不算整机通过。
