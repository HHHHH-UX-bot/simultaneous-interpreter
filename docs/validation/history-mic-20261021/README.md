# 历史页版本的真实麦克风复测与交接

2026-10-21，用户要求增加历史页后再测真实麦克风，随后要求把问题及设置页下一阶段提交GitHub交给队友。结论是**字幕预览与历史交互可用，定稿/记录完整性仍不通过**。本次未改业务代码、重载程序或配置PL；未自动暂停/重连。输入来自实际麦克风，不是20条UI示例或固定音频播放。

## 对象与方法

[session](session.json)绑定Z7-Nano、JTAG线缆210241277120、同音频PL（USR_ACCESS=0x5a375458）及历史页真实麦克风ELF `e02b03dc993023c0e5aad9decb2055b1f4c58aeecf1fedcff9292c51ad5d4705`。PL只读预检DONE/EOS=1、CRC=0通过。界面/构建与前次加载证据仍见[历史页验证](../history-ui-20261021/README.md)，不改写其原范围。

用户在就绪后说“Good morning.”和“I would like a cup of coffee.”；之后查看实际历史页。观察器只读公开计数、队列就绪标记和音频环形缓冲头；不停止CPU0，不抓持续上传中的整帧。没有导出原始PCM、识别文本或朋友谈话内容。冻结的[采样工具](sample.py.txt)、[观察器](watch.py.txt)和[只读预检](preflight.py.txt)使用当次ELF符号及135768/135832模型/快照ABI，不能直接用于别的构建。

## 观察结果

完整记录见[observation](observation.json)，解读与差值见[summary](summary.json)。24个采样首尾相隔182.5秒，期间用户操作过暂停/继续，因此分会话解读：

| 范围 | 实际结果 |
| --- | --- |
| epoch3，同会话95.2秒 | ASR final=12→12，翻译事件15→18，committed/history=12→12；用户确认两句都有新英文/中文且画面正常，但两句未进入历史 |
| 同会话队列现场 | 6个条目翻译完成但source_final_ready=0；顺序13/14/15无原文文本，16/17/18已有原文文本却未定稿。标记只是现场，尚不能解释缺事件的真实来源 |
| 手动暂停/继续 | 用户明确确认点过；采样看到epoch3→4→5及连接重新就绪。不能把重连后的ASR/committed计数与旧会话直接相减 |
| epoch5 | 新会话ASR final=2、committed=2；累计真实历史12→14。用户确认自己的第三次coffee句及交谈中有记录入历史；不导出交谈内容，也不把两条记录强行映射为最初两句 |
| 上传与错误 | 全窗口上传+1119页；丢页=0、串口溢出/帧错=0、采样溢出=0。云失败开机累计1→1、TLS失败0→0；保留既有失败值，不能写成从未发生云失败 |
| UI与返回 | 历史页期间仍在上传；最大绘制记录41ms。结束后[返回字幕命令](return_main.log.txt)被接受，随后[实读](returned_main.json)为epoch5、主字幕页、历史14、网络4/error0、client4；[CPU1触摸采样](touch_sample.json)通过 |

[用户口述验收](physical_speech.json)和[历史检查/操作说明](physical_history.json)分别保存。用户所见和公共计数共同支持“前两句没有完整记录”，不能将实际对话的记录混作指定测试句已通过。

- 真实采音上传、英中字幕预览、实际画面及历史页能工作；历史能接收真实新定稿。
