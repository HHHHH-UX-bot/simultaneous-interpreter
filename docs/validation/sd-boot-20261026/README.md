# SD 卡独立启动验证（2026-10-26）

对象：Z7-Nano 7010，线缆 210241277120；32 GB TF 卡（FAT32）；Vivado/Vitis 2026.1 构建。设计见 [SD_BOOT](../../design/SD_BOOT.md)。JTAG 只做只读检查和下文注明的实验，没有替代启动过程。

## 构建

- PS 平台：在现有配置上只加 SD0（MIO40–45）和 UART0（MIO14–15）。生成的 `ps7_init` 与 JTAG 用的逐行对比，只多出 SD/UART 时钟、外设时钟门控、上述 MIO 和 UART0 寄存器；DDR、PLL 完全相同。PL 位流沿用已验证的 `97ddda29…`。
- FSBL：2026.1 已禁用 XSCT，改用 Vitis Python 接口生成；中文 Windows 上需 `chcp 65001`，否则 Vitis 服务的 GBK 输出会让接口崩溃。钩子与 `FSBL_DEBUG` 编入，FSBL 占用 OCM 至 0x1C8D0。
- 跳板与装载包：13 段，入口 CPU0 `0x10000`、CPU1 `0x1000`；`BOOT.BIN` 411,858,276 字节。
- JTAG 预测试：把装载包和跳板写入 DDR，由跳板启动 CPU0。启动信息块、CRC 与入口正确，应用显示报告 `0x600d600d`。
- 配置文件工具用假数据自测：552 字节，与 C 结构布局、CRC 一致。用户输入真实凭据后直接写卡，回读只核对头部与 CRC。

## 三次上电

| 次序 | 现象 | 原因与处理 |
| --- | --- | --- |
| 1 | 启动、凭据、TLS 联网和板上 Qwen（FSBL 装载，固件 SHA 复核、引擎初始化）都通过；屏幕黑、无触摸 | CPU1 的 ULPI 首次写超时（错误 6），端口未供电。JTAG 加载器原先会先做一次 USB 预上电；改为 CPU0 执行同一序列。另：音频模块在切跳线时被拔下未插回，编解码器无应答 |
| 2 | 屏幕在 HDMI 之后才通电，触摸屏被枚举但不发报告；识别无输入 | 实验：干净停 CPU1，断开屏幕供电 3 秒再供电 3 秒后重启 CPU1，点击即收到 254 个报告。改为显示启动前供电、满 5 秒再唤醒 CPU1。音频模块插回后编解码器应答，但 BCLK 未起振，需要完整断电 |
| 3 | 屏幕自己亮，用户确认触摸和识别都正常 | 见下 |

第 1 次运行约 312 秒时云端发来 WebSocket 关闭（1007）；当时音频模块未接、没有麦克风数据，之后没有再现。

## 第 3 次上电的只读检查

- BOOT_MODE=5；启动信息块正确；配置已应用并从 OCM 清零。
- 随机数混入 2048 个实时麦克风采样；音频状态 `0x0b0006a3`，采样计数增长。
- 网络阶段 4、云客户端就绪，62 个云事件、0 错误。
- PORTSC `0x80001805`，CPU1 主机状态正常，已收到 126 个触摸报告。
- 声纹加速器模型有效、帧计数增长。
- 板上 Qwen：FSBL 把两份资产装入 DDR，固件开机后全量 SHA256 复核通过（两份均 ready），引擎初始化完成、错误 0。本次没有单独测板上推理（第 1 次上电时用户已确认过云端 ASR → 板上 Qwen → TTS 链路）。

## 未验证

- 用新 ELF 走 JTAG 流程只验证到显示启动（预测试）；SD 相关代码在 `BOOT_MODE` 不为 SD 时不执行。
- 长时间运行、反复冷启动的成功率、卡的读取速度差异。
- 凭据明文在卡上、TLS 时间基准与“尚未生效”放宽等安全取舍见 [R34](../../context/RISKS.md)。
