# 连续长句优化与验证（2026-10-22）

已完成SDK2018.3重编译、JTAG加载并恢复正式真实麦克风。桌面目录仍为 `simultaneous-interpreter-tts-20261021`，默认中文译英文，可切英译中；屏幕USB供电开启、CPU1触摸运行，设置和UI风格保留。

## 本次修改

- UART由1Mbaud提高到2Mbaud，保持ARM可信TLS、确认上传、主动IPD下行和有界批量解析。
- 固定点Opus从Os改为O2编译，保持24kbps、复杂度5、DTX和20ms帧；未修改默认1.0x、24kHz PCM、音量与音频采样顺序。
- 修复连续IPD包的CRLF空行累积：旧代码会把512字节AT回复缓冲区填满，触发错误25，使后续字幕和译音一起停滞。包头/空行剥离和回复长度/行偏移现在同步处理，未增加隐式重试。
- CPU1触摸/USB服务按每毫秒一次执行，减少空闲时的重复总线访问。两个独立云会话均启用此CPU1；延迟仍受云端/无线波动影响，不把两轮差异全归因这项改动。

## 失败记录与回归

- 未修解析器的2M变体带CPU1复测，在98.880秒触发错误25，回复长511字节，脱敏前256字节全是CRLF。其后UART溢出77692是停止收包后的次生现象，不能反推为首个硬件故障。失败保留于 `baud2m_o2/with_touch/latency.json`。
- 原生600个1字节IPD包、拆分包头且延后SEND OK：修前同样错误25，修后155201项检查通过，131672下行/20481上行字节逐一一致。20组播放、AT/TLS和恢复回归通过。
- 修解析后、尚未节制CPU1的 `baud2m_fixed/run_001` 内容完整，但有23个硬件欠载计数/14次起播，判定失败并保留，未作为最终通过结果。
- 早期单独2M-O2/1.67M测试未运行CPU1，存在较快的3.378秒译文记录；它们只用于诊断，不替代上表两次实际产品配置。
- 批量JTAG读MMIO曾产生不可靠计数；现在逐个读外设寄存器。大块调试读取在持续音频时也曾造成85.91ms服务空档和真实UART溢出；最终两轮等输入/播放结束后再取日志。不能据旧批量读数断言2M物理帧错误。
