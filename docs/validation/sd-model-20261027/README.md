# SD 启动后台加载板上模型验证（2026-10-27）

对象：Z7-Nano 7010 SD 启动；Vivado/Vitis 2026.1、ARM GCC 13.4。设计见 [SD_BOOT](../../design/SD_BOOT.md#板上模型后台加载2026-10-27)，决定见 [D26](../../context/DECISIONS.md#d26-sd-启动后台加载板上模型2026-10-27)。

先完成构建与主机测试；用户回来后写卡、上电，并用 JTAG 只读记录启动与加载过程（不停核、不写内存）。

## 改动

- `BOOT.BIN` 去掉 Qwen 两个分区；Qwen 改为卡上 `qwen.tqw`、`qwen.tok`，由 `scripts/write_sd_card.py` 写入并回读核对。`build_sd_boot.py` 拒绝打包不含加载器的旧应用。
- 新增 `software/network_ui/sd_model.c`：启动稳定后解析 FAT32、按簇链用 ADMA2 读入原固定窗口、分片 SHA256，经 `remote_display.c` 的固定摘要判定就绪；加载期间锁住电脑上传入口。SD 启动时不再运行热重载复核。
- 界面：模型页状态行与进度条、任意页面约 4 秒的就绪通知、本地模式就绪前的“本地模型正在准备”。板上 Qwen 构建的模型 135996 字节、快照 136060 字节；`z7_nano_capture.tcl` 已接受新尺寸。字库子集重新生成，新增 13 个字符（432 个），字库载荷上界 2,191,158 字节。

## 板上（2026-10-27）

写卡：`write_sd_card.py` 在 PowerShell 中以卷路径运行，三个文件写入并回读一致，共 23 秒。Git Bash 会改写 `\\?\Volume{…}\` 参数，不能在那里传卷路径。

时间均为 JTAG 读到的板上计数。FSBL 的运行库把全局计时器从 0 启动，所以“计时器值 − 应用时间”就是上电到应用启动的耗时。

| 项目 | 结果 |
| --- | --- |
| 上电 → 应用启动 | 5.53 秒；同一块板此前运行的旧版（`BOOT.BIN` 含 Qwen）为 28.8 秒 |
| 首帧 | 应用启动后约 0.8 秒；用户确认触摸、识别正常 |
| 开始读卡 | 应用 5.49 秒（屏幕、触摸、配置就绪后） |
| 读卡 | 99 条读命令共 406,915,684 字节，约 25 秒读完（峰值约 24 MB/s） |
| 校验与就绪 | 校验约 3.3 MB/s，是瓶颈；应用 128.45 秒两份摘要一致、引擎初始化完成；模型页状态 2→3、百分比 1→100 逐步上升 |
| 就绪通知 | 状态变为就绪时出现，约 4 秒后撤下（JTAG 读快照字段，用户未单独描述画面） |
| 画面 | 全程无视频欠载/格式错误；绘制最长 68 毫秒（平时约 25 毫秒） |
| 本地翻译 | 网络恢复后两句：第一句识别结束到板上 Qwen 完成约 40 秒（预填充约 31 秒），随后播出译音；第二句 14.5 秒，之后 TTS 服务返回错误，本地模式停在错误态 |

开机后云端会话自动开始，校验一直按“会话进行中”的 150 µs 时间片运行，所以约 3.3 MB/s；读卡本身只用约 25 秒。

### 网络中断（与加载无关）

同次运行出现两次 ESP8266 对 CIPSEND 30 秒无应答（网络错误 27）：应用 95 秒（云端串流中，正在校验）和 304 秒（切到本地模式后，校验早已结束）。PL UART 溢出与帧错误计数均为 0，说明板端没有丢字节。云端模式自行重连；本地模式进入错误态后，暂停/继续时残留的网络故障立即再次触发错误，直到切回云端恢复网络后再切回本地才继续。用户认为可能是接线松动，云端也遇到过，本轮不处理，记为 [R35](../../context/RISKS.md)。

## 未验证

- 用户未单独描述进度条和通知的画面效果；以上状态来自 JTAG 读到的快照字段。
- 无会话时（空闲时间片 600 µs）的加载速度；反复冷启动的稳定性。
- 进一步提速的两个方向未实施：跳板关缓存逐位算 CRC（推测是 5.5 秒中的主要部分），以及会话中的校验时间片。
